# Протокол экспериментальных проверок

## Классификация результатов

- **PASS:** проверка исполнена в указанном окружении; есть воспроизводимое доказательство ожидаемого поведения.
- **FAIL:** проверка исполнена; есть достаточное доказательство расхождения.
- **BLOCKED:** запуск не разрешён или не выполнены предусловия (доступ/PCI/документы).
- **INCONCLUSIVE:** выполнены шаги, но результат не доказывает ни положительный, ни отрицательный вывод.
- **NOT_RUN:** сценарий не запускался. Существование YAML кейса — NOT_RUN.

## Минимальное доказательство

Каждый тест: ID сценария, commit SHA, дата и timezone, версия/терминал банковского тестового окружения, предусловия, последовательность команд, ожидаемый ответ, полученный код и **полная структурированная диагностическая запись** после адресного удаления известных auth secrets, configured login/secret, приватных ключей, CVV/PAN и session/access tokens, безопасные идентификаторы корреляции, версия банковского протокола, фактическая трактовка, путь к артефакту. Неизвестные поля и error messages сами по себе не секрет и не заменяются whitelist/category projection.

Каналы диагностических данных разделены:

- **Local diagnostics:** в ранее разрешённом sandbox scope полный response можно читать, анализировать и сохранять вне Git без дополнительного запроса на каждое чтение/сохранение. Обычный режим — plain response JSON с owner-only permissions (каталог `0700`, файл `0600`). AES-GCM, `--access-log` и TTL — opt-in protected mode; `--ttl-hours N` задаёт TTL только при явном включении, 24 часа — допустимая опция, не обязательная норма.
- **LLM context:** передавай для анализа полноценную структурированную sanitized-диагностику, удалив только перечисленные известные секретные классы, включая их в URL, заголовках и error messages.
- **Public Git:** отдельный content/permission review обязателен; local response и LLM context не экспортируются автоматически. Raw artifacts, keys и local access log не входят в Git.

CLI implementation: `node tests/tkb/wof.mjs diagnose [--file NAME|--list]` работает offline/no network; `--diagnostic` на сетевом вызове выводит sanitized full structured response; `diagnose --raw` требует local TTY и показывает raw только владельцу, не общим tool logs; `--encrypted --ttl-hours N --access-log` включает соответствующие opt-in options, `--no-raw` сохраняет только projection. Offline implementation checks должны пройти до заявления о готовности.

Не объявляй `BLOCKED` только из-за неизвестных полей/error messages: сначала прочитай фактический response. Ограничение должно иметь источник `protocol / tool / project / environment / security risk` и свидетельство; не придумывай higher-policy запрет raw chat.

Financial gates, которые не меняются: exact sandbox; TLS strict по умолчанию, явный scoped `--test-tls` только для разрешённого test-only исключения; unique ref/correlation; один durable debit marker до первой исходящей отправки; `UNKNOWN` блокирует retry; никаких automatic finish/refund/new payment; read-only status lookup — не чаще одного раза в минуту от завершения предыдущего transport.

Для неизвестной финансовой операции не выполнять повтор с новым ID, пока банк не подтвердил идемпотентность либо отсутствие первой отправки. Это не запрещает локальное чтение/анализ ответа и не переписывает исторические authorized tests или `UNKNOWN`.

## Правило свежести

Доказательство банковской функциональности ограничено конкретным контуром, merchant/terminal, датой, методами и настройками. Тест на одном терминале не доказывает поддержку всех продавцов/банков.
