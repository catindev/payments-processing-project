# Протокол экспериментальных проверок

## Классификация результатов

- **PASS:** проверка исполнена в указанном окружении; есть воспроизводимое доказательство ожидаемого поведения.
- **FAIL:** проверка исполнена; есть достаточное доказательство расхождения.
- **BLOCKED:** запуск не разрешён или не выполнены предусловия (доступ/PCI/документы).
- **INCONCLUSIVE:** выполнены шаги, но результат не доказывает ни положительный, ни отрицательный вывод.
- **NOT_RUN:** сценарий не запускался. Существование YAML кейса — NOT_RUN.

## Минимальное доказательство

Каждый тест: ID сценария, commit SHA, дата и timezone, версия/терминал банковского тестового окружения, предусловия, последовательность команд (очищенные тела или структурный шаблон), ожидаемый ответ, полученный код и нормализованные поля ответа, безопасные идентификаторы корреляции, версия банковского протокола, фактическая трактовка, путь к артефакту.

Для неизвестной финансовой операции не выполнять повтор с новым ID, пока банк не подтвердил идемпотентность либо отсутствие первой отправки. Скрытые/чувствительные данные не включать даже в «закрытый» отчёт Git.

## Правило свежести

Доказательство банковской функциональности ограничено конкретным контуром, merchant/terminal, датой, методами и настройками. Тест на одном терминале не доказывает поддержку всех продавцов/банков.
