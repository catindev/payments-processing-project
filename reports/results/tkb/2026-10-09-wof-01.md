## Гипотеза и границы протокола

Кандидат `POST /api/v1/card/unregistered/debit/wof` из Postman принимает вложенный CardInfo и регистрирует тестовую оплату на 100 копеек. Наблюдаемый ответ позволит различить validation/access error, необходимость банковского 3DS действия и возможные финансовые признаки. **HTTP200/errorCode0/OrderId не объявляются paid.**

[Документальный обзор](<wof-protocol-review.md>) подтверждает только sample-backed topology: ExtId, Amount:number, Description:string, CardInfo.{CardNumber,CardHolder,ExpirationYear,ExpirationMonth,CVV}. Текущая required/type schema, формат года и финальные status codes не предоставлены. Bare expiry placeholders разрешаются локально. В первом candidate приняты YYYY integer/month integer и numeric CVV по sample type; CardHolder — явно фиктивный TEST CARD. Эти технические допущения НЕ объявляются утверждёнными банковскими нормами. PascalCase sample names сохраняются в отправляемых bytes; changelog сообщает case-insensitive lowerCamelCase normalization, а не необходимость слепо менять поле.

Приватный test-only карточный fixture зашифрован AES-GCM, ключ/файл owner-only и находятся вне Git-root; реквизиты не повторяются/не пишутся в reports или исходники. Обычный Merchant API/Core/telemetry не используется. Это изолированный research harness, **не PCI-ready контур и не собственный production Checkout**.

## Предусловия и шаги

1. Offline tests: HMAC, строгий whitelist evidence, запрет reflection secret-as-key, correlation mismatch, paid status не превращается в financial success.
2. Exact HTTPS origin hash, root source URL без userinfo/query, explicit `--run --test-tls`, fixed endpoint enum init/lookup; hostname check до отправки headers/body, Agent локальный, timeout15s, response64KiB, no redirects/retry/global TLS mutation.
3. `prepare`: проверить test-only fixture и создать durable ledger с immutable ExtId, amount/currency, единичным budget; duplicate ledger creation запрещено.
4. `init`: exclusive durable dispatch_started marker + fsync **до возможной отправки**; один POST. Никакой сброс gate после timeout/crash/ошибки записи.
5. Сохранить только построенный typed whitelist результата: codes/classification/shape, masked/hash correlation, amount/currency match, action-data presence. Нет raw messages/body/token/карточных значений.
6. При необходимости `lookup` по тому же ExtID: durable exclusive sequential marker + обязательный completion предыдущего lookup, shared ref budget max3; интервалы **60 секунд после завершения/закрытия предыдущего transport** по monotonic+wall clock. In-flight/uncompleted marker блокирует следующий lookup независимо от прошедшего времени; markers не auto-expire и не удаляются. No not_found-to-failed и no unlock replay.
7. Legacy `/wof/finish` с md/paRes не подменяется 3DS2 `/3ds2/wof/finish` с AuthenticationData. В текущем harness continuation endpoints **не активированы** до фактического ответа/сверки. No no3ds/OTP spoofing/автовозврат.

## Ожидаемое / остановка / восстановление

Ожидается документируемый bank response на candidate; если нужны 3DS действия — только bank-supplied, correlated и sandbox-scoped. Неизвестные/конфликтные/недокументированные ответы остаются INCONCLUSIVE, неизвестный эффект сохраняет consumed gate. Референс ExtId уникален, но не доказывает bank idempotency.

При возможной отправке timeout/5xx/parse failure/response cap/write failure — unknown, деньги не повторять, банк не переключать. Никаких automatic refund/void/reverse для cleanup. После initial send финансовый rollback — только отдельное доказанное действие с разрешением; тестовый budget не увеличивается самовольно.

## Воспроизведение (до запуска)

```bash
node tests/tkb/wof.mjs                 # offline only
node tests/tkb/wof.mjs prepare         # local durable reservation, no network
node tests/tkb/wof.mjs inspect         # local safe state, no network
node tests/tkb/wof.mjs init --run --test-tls
node tests/tkb/wof.mjs lookup --run --test-tls  # read-only bank state, rate-gated
```

Не удалять private ledger/markers ради повторного запуска; это не resettable demo. Исходный environment и encrypted fixture/ключи не коммитятся.
