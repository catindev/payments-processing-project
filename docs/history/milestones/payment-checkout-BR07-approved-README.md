# BR-07: согласованная собственная карточная форма — v0.12

Дата 2026-10-09. Пользователь явно уточнил, что «своя платёжная форма» означает **собственный ввод реквизитов карты**, а не промежуточную страницу, после которой покупатель вводит карту у банка. BR-07 утверждён как продуктовое требование.

## Продуктовый критерий готовности

- Наша платёжная форма: брендированный минималистичный UI, единый акцентный цвет, реальные поля ввода карты, поддержка 3DS.
- Использование документированного и разрешённого банковского WOF/direct API (ТКБ — первый кандидат) через защищённый PCI-контур, исключающий PAN/CVV из общего Payment Core, merchant API, логов, событий и БД общего назначения.
- Банковская hosted-форма для банков без доступного прямого API, но **она не замещает** обязательный собственный ввод карт.
- Если доступны только QR СБП и redirect на форму банка, это ограниченный технический пилот, но не выполнение BR-07.
- Успех/отказ оплаты всегда определяется банковскими фактами по общей модели Payment/PaymentIntent.

## Что остаётся открытым

1. Подтвердить права терминала ТКБ на WOF и последовательность 3DS2/ACS/Finish.
2. Определить PCI DSS объём и необходимое подтверждение соответствия, включая согласование с эквайером и QSA.
3. Решить, допускается ли иной защищённый способ ввода карты (например, hosted fields) как реализация требуемого UX.
4. Согласовать план этапов: ограниченный пилот отдельно или сразу полноценный BR-07 выпуск.
5. Выполнить испытания тестового контура; описанные контрактные сценарии — только спецификация проверок.

**Статус:** бизнес BR-07 согласован; архитектурные детали и банковская/PCI готовность НЕ подтверждены.
