# Checkout UI — новая продуктовая потребность, проект v0.11

**Дата:** 2026-10-09.

Новый продуктовый запрос заказчика: собственный checkout-пейдж, повторное использование UI старых проектов; приоритет WOF/direct API банка там, где это разрешено и безопасно, иначе bank-hosted redirect. Не входит в прежний перечень BR-01—BR-06 и **не подменяет их согласование**.

Файлы:
- `payment-checkout-design-v0.1.md` — новая область анализа: режимы, 3DS, PCI DSS, fallback и открытые вопросы.
- `payment-processing-decisions-v1.0.md` — журнал прежних согласованных решений плюс новый BR-07 со статусом «продуктовое требование озвучено, техрешение проект».
- `payment-processing-architecture-v1.0.md` — архитектура + новая глава Checkout.
- `payment-lifecycle-spec-v0.11.md` — жизненный цикл + сценарий UI (без новых финансовых статусов).
- `payment-api-v0.11.openapi.yaml` — проект дополнений: `checkout.url`, эффективные `MethodCapability.forms`, отсутствие карточных данных в Merchant API.
- `acquirer-connector-v0.6.ts` — две формы источника карты в SPI: hosted и `secure_card_ref` без PAN/CVV.
- `acquirer-connector-contract-v1.0.md` — контракт подключения нового режима.
- `tkb-connector-profile-v0.2.yaml` — перечень документированных методов TKB WOF/3DS2, все права/фактические доступности unknown.
- `checkout-contract-cases-v0.1.yaml` — **22 сценария для будущих испытаний; не выполнялись**.

**Важно:** ТКБ предоставляет WOF методы, которые принимают CardInfo с PAN и CVV. Без PCI DSS готовности изолированного контура включать прямой режим нельзя. Уже сейчас доступен собственный UX для QR СБП и перехода на банковскую карточную форму. Документальные возможности не объявляются проверенными на стенде.

Схемы OpenAPI и TypeScript проверяются статически, но ничего не исполняет банковских операций. Не включать никакие реальные креды из переданного Postman environment в результирующий архив.
