# BR-03.2 и NAME-01 — согласование v0.7

**Дата:** 2026-10-09. **Согласовано заказчиком:** BR-01, BR-02, BR-02.1, BR-03.1, BR-03.2, NAME-01. **Открыто:** BR-04—BR-06 и банковская верификация отдельных методов.

## Решения

- В управляемом режиме окончательное частичное списание дочернего Payment только с явным `reduce=true`; сумма намерения `amount` неизменна, `amount_final` устанавливается после подтверждённого банковского итога. `amount_paid` отражает фактическое списание.
- `Payment` и `PaymentIntent` становятся `succeeded` по доказанному финальному списанию, в том числе меньшей суммы. Возвраты не меняют этот статус/первоначальную сумму; сведения об отгрузке не являются предметом платёжного ядра.
- Остаток не подлежит второму capture в рамках v1/завершённого намерения. Многократные списания — отдельное расширение.
- Новая конвенция NAME-01 требует максимум два смысловых слова в имени поля, предпочтительно одно. Полные определения — в описаниях.

## Технические изменения в проектном API

- `CaptureRequest` в публичном v1: только `amount` и опциональное `reduce`; старое `final_capture` удалено за ненадобностью: каждый capture в первом выпуске окончательный.
- В `PaymentIntent` добавлено `amount_final`; остальные имена из трёх и более слов сокращены без изменения бизнес-смысла.
- Внутренний банковский интерфейс тоже переименовал многословные собственные поля; значения исходного банковского API не менялись.
- Эти переименования несовместимы с предыдущими черновиками v0.6, но до публикации внешнего API сохранять обратную совместимость не требуется. При последующих переходах версии это должно решаться отдельно.
