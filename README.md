## Как начать из архивного handoff (исторические инструкции)

1. Создайте **приватный** Git-репозиторий и распакуйте содержимое *этого каталога* в его корень. Не загружайте оригинальные банковские Postman environment, ключи или карточные данные.
2. Прочитайте `AGENTS.md` и `handoff/PROJECT_CONTEXT.md`, затем `docs/current/payment-processing-decisions-v1.1.md`.
3. Установите зависимости статической проверки: `python3 -m pip install -r requirements-validation.txt`.
4. Запустите `python3 scripts/validate_current.py`. Это **статические проверки**, не исполнение 245 сценариев и не запросы в банк.
5. Передайте агенту `handoff/START_PROMPT.md` и задачу `tasks/001-tkb-wof-3ds.md`. Подготовьте тестовый доступ и полные банковские документы **вне Git**.
6. Агент фиксирует результаты по `reports/templates/experiment.md`, сохраняет очищенные доказательства в ветке и создаёт PR. Изменения нормативных требований не проводить без отдельного согласования.

## Ключевое продуктовое правило

Собственная платёжная форма (BR-07) — не оболочка со ссылкой на банк. Покупатель вводит карту в **нашей форме**; наш защищённый контур работает с разрешённым банковским API (первый кандидат — TKB WOF). Банковская hosted-форма — fallback для несовместимых банков. Выпуск только с bank-hosted редиректом **не закрывает BR-07**.

## Границы безопасности

Не включены: оригиналы TKB PAY (`*.doc`), Postman collection и environment, банковские исходники `payform_rest-develop.zip`, старые пользовательские frontend-архивы, реальные секреты и сетевые дампы. Этот архив содержит **только разработанные в беседе материалы** и новый рабочий handoff. Получайте полные исходные банковские материалы напрямую у владельца и храните по внутренним правилам доступа. Не копируйте их в публичный репозиторий.
