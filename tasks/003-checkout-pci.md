# TASK-003 — Новый Checkout / PCI-границы

**Цель:** спроектировать проверяемый Checkout на основе проекта `pyment-form`, отдельного 3DS frontend и примера банковской формы TKB. Не копировать банковские исходники без прав.

1. Уточнить владельца PCI проекта и допустимый способ обработки PAN/CVV. Потребуются оценка scope и согласование с банком/QSA.
2. Выделить design tokens: merchant `accent`, вычисляемые цвета/контраст и фиксированные системные цвета ошибок.
3. Checkout UI показывает свои поля карты для direct/WOF и QR для СБП; provider fallback переводит на форму банка только когда это разрешено и безопасно.
4. Карточные реквизиты ни при каких обстоятельствах не должны попадать в Merchant API, core, logs, webhooks, browser analytics, общие APM traces, Postman output или историю чата.
5. 3DS challenge выполняет ACS; отдельный 3DS frontend репозитория можно использовать как reference, но не предполагать, что нужно разворачивать отдельное приложение.
6. Начальные mock тесты без настоящих карточных реквизитов; финансовые банковские тесты только после разрешений.

Результат: boundary diagram, threat model, UI contract, список переиспользуемых компонентов и 30 проверок `docs/current/checkout-contract-cases-v0.2.yaml` с реальными статусами.
